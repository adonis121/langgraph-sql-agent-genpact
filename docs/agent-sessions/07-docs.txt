     4. docs/known-limitations.md (new)

     - The multi-step question can be read two ways ("failed ... taught by that
       teacher": in Fall
       2025 or in any semester). The eval tests both readings as separate
       questions (#9, #10).
     - The eval comparison is lenient: extra agent columns are allowed, only the
       last step is checked,
       rows are compared as sets, numbers are rounded. It is also strict: exact
       values only (#6 fails on
       shape). It is one run per question, so nondeterminism is not measured.
     - The eval reference for "best teacher" uses LIMIT 1 (ties not covered;
       fine on the seed data).
     - The read-only guarantee only exists for SQLite: connect_readonly refuses
       other engines.
     - LIMIT is not universal (TOP); a LIMIT anywhere counts; 200-row cap; the
       answer sees 50 rows.
     - The keyword check is a denylist (the read-only DB is the real boundary).
     - Behaviour that depends on prompt rules is not guaranteed (ask about
       shared names, never widen on retry).
     - At most one clarification; InMemorySaver (a pause doesn't survive a
       restart).
     - Later steps copy ids from earlier result tables through the prompt
       (bounded by the rows shown).
     - The full schema goes into every prompt (fine for 6 tables, not for 600).
     - No statement timeout. No SQL-error retry / give_up example trace from a
       real run yet.
     - Any other gaps found while writing the docs.
